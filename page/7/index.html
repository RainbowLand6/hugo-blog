05-理解 Pipeline 与 Jenkinsfile

为什么不一直用自由风格任务

自由风格任务的配置主要保存在 Jenkins 页面中。它的问题是：

  • 配置不容易和代码一起审查。
  • 换 Jenkins 或恢复环境时迁移麻烦。
  • 多个任务的步骤容易复制粘贴后逐渐不一致。

Pipeline 把流程写进代码，通常放在项目根目录的 Jenkinsfile 中并提交到 Git。

06-编写第一个 Declarative Pipeline

本章不依赖 Git 仓库，直接在 Jenkins 页面运行第一条 Pipeline。

新建 Pipeline 任务

  1. 点击 New Item。
  2. 名称输入 first-pipeline。
  3. 选择 Pipeline。
  4. 在 Pipeline 区域将 Definition 选择为 Pipeline script。
  5. 粘贴下方脚本并保存。
pipeline {
    agent any

    stages {
        stage('准备') {
            steps {
                echo '开始执行流水线'
                sh 'java -version || true'
            }
        }

        stage('构建') {
            steps {
                sh 'mkdir -p output && echo "build-${BUILD_NUMBER}" > output/result.txt'
            }
        }

        stage('验证') {
            steps {
                sh 'test -f output/result.txt'
                sh 'cat output/result.txt'
            }
        }
    }

    post {
        success {
            echo '流水线执行成功'
        }
        failure {
            echo '流水线执行失败，请查看失败阶段的控制台日志'
        }
        always {
            archiveArtifacts artifacts: 'output/**', allowEmptyArchive: true
            cleanWs()
        }
    }
}

如果页面提示找不到 cleanWs，说明没有安装 Workspace Cleanup 插件。先删除这一行继续练习，或安装该插件后重试。

12-安全、备份、监控与故障排查

Jenkins 一旦能部署代码，就已经是重要系统。最后一章把日常最关键的维护动作集中起来。

安全基线

  • 不要把 Jenkins 直接裸露在公网。
  • 启用登录认证；团队环境按角色分配权限，不共享管理员账号。
  • 凭据保存在 Credentials，不提交到仓库，不打印到日志。
  • Controller 尽量只负责调度，构建在隔离 Agent 中执行。
  • 定期升级 Jenkins LTS 和已安装插件，升级前先备份。
  • 审核谁能修改 Jenkinsfile。能修改流水线的人，通常也能影响部署动作。

备份什么

Docker 安装时，核心数据在 /var/jenkins_home，也就是本教程的 jenkins_home 数据卷。
