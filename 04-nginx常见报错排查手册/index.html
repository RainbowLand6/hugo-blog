Nginx 常见报错排查手册

这篇文章不讲太多原理，重点讲一件事：

Nginx 出问题时，你该先看什么、怎么判断、怎么处理。

很多人碰到报错时，第一反应是反复改配置。
但大多数时候，问题不是“多改几次就会好”，而是“先找对方向”。

所以这篇手册按下面的方式来写：

  1. 报错现象
  2. 常见原因
  3. 排查步骤
  4. 常见解决办法

你可以把它当成日常查错清单。

一、先记住一个总排查顺序

不管你遇到什么问题，建议先按这个顺序来。

1. 先检查配置语法

nginx -t

如果这里都没过，后面很多判断都没意义。

2. 再看 Nginx 错误日志

常见位置：

logs/error.log

或者：

/var/log/nginx/error.log

3. 再看访问日志

常见位置：

logs/access.log

或者：

/var/log/nginx/access.log

4. 再确认请求到底进没进 Nginx

有些问题根本不是 Nginx 自己报的，而是：

  • 域名没解析对
  • 端口没开放
  • 请求没进这台机器

5. 最后再去看后端服务

尤其是：

  • 502
  • 504
  • 接口返回异常

这类问题经常不在 Nginx 本身，而在后端服务。

二、nginx: [emerg] 配置语法错误

常见现象

执行：

nginx -t

或者重载时看到类似：

nginx: [emerg] unexpected ...
nginx: configuration file ... test failed

常见原因

  • 少了分号 ;
  • 大括号没配对
  • 指令写错位置
  • 指令名字拼错
  • 引号没闭合
  • include 的文件本身有问题

排查步骤

  1. 先看报错里提示的文件路径
  2. 再看提示的行号
  3. 重点检查这一行以及上下几行
  4. 看是不是前面少了分号，导致错误在后面才暴露

常见解决办法

例如这类错误：

server {
    listen 80
    server_name example.com;
}

问题在这里：

listen 80

少了分号。

应改成：

listen 80;

一句话建议

看到语法报错，先别猜，先看行号。

三、启动失败：端口被占用

常见现象

Nginx 启动失败，或者启动后访问不了。

常见提示类似：

bind() to 0.0.0.0:80 failed

常见原因

  • 80 端口已经被其他程序占用了
  • 443 端口已经被其他程序占用了
  • 同一端口被重复监听

排查步骤

  1. 确认你配置里监听的是哪个端口
  2. 确认这个端口是否已被其他程序占用
  3. 确认是否有多个配置块重复占用同一个监听方式

常见解决办法

方案 1：换端口

listen 8081;

方案 2：停掉占用端口的程序

比如可能占用 80 端口的有：

  • Apache
  • IIS
  • 旧的 Nginx 进程
  • 某些开发工具

一句话建议

启动不了，先怀疑端口，不要先怀疑配置逻辑。

四、403 Forbidden

常见现象

浏览器能访问到 Nginx，但返回：

403 Forbidden

常见原因

  • 目录权限不够
  • 网站目录里没有首页文件
  • root 路径写错
  • 目录本身不允许列出
  • 请求进了一个本来就不允许访问的路径

排查步骤

  1. 看 root 指向的目录是不是你以为的那个目录
  2. 看目录里有没有：
    • index.html
    • index.htm
  3. 看 Nginx 运行用户是否有读取权限
  4. 看是不是命中了某条禁止访问规则

常见解决办法

场景 1：没有首页文件

location / {
    root /data/www/site;
    index index.html index.htm;
}

如果目录里根本没有 index.html，就容易出问题。

场景 2：权限不足

Nginx 进程用户没有权限读取目录或文件。

这时要改目录权限，而不是一直改 location。

一句话建议

403 大多不是“服务挂了”，而是“能找到地方，但不让你看”。

五、404 Not Found

常见现象

浏览器返回：

404 Not Found

常见原因

  • 路径写错
  • location 没匹配上
  • 文件不存在
  • root / alias 写错
  • 前端单页应用没配 try_files
  • 反向代理的后端本身返回了 404

排查步骤

  1. 先确认请求路径到底是什么
  2. 再确认请求进了哪条 location
  3. 如果是静态资源：
    • 看真实文件是否存在
    • 看 root 或 alias 是否正确
  4. 如果是前端单页应用：
    • 看有没有 try_files $uri $uri/ /index.html;
  5. 如果是接口：
    • 看后端本身是否返回了 404

常见解决办法

场景 1：单页应用刷新 404

location / {
    root /data/www/app;
    index index.html;
    try_files $uri $uri/ /index.html;
}

场景 2：静态目录映射错误

location /images/ {
    alias /data/static/images/;
}

如果这里写成了不合适的 root，就可能找错路径。

一句话建议

404 要先分清：
是 Nginx 找不到，还是后端找不到。

六、405 Not Allowed

常见现象

请求路径能访问到，但某种请求方法不被允许，比如：

  • GET 可以
  • POST 不行

常见原因

  • 后端服务不支持该请求方法
  • 某些静态目录只适合 GET
  • 反向代理后端时，请求被后端拒绝

排查步骤

  1. 先看是不是静态资源路径
  2. 再看是不是后端接口限制了方法
  3. 查看后端服务日志

一句话建议

405 多半不是 Nginx 路径找不到，而是请求方法不被接受。

七、413 Request Entity Too Large

常见现象

上传文件时报错：

413 Request Entity Too Large

常见原因

  • 上传文件超过 client_max_body_size

排查步骤

  1. 看当前请求命中的是哪条 location
  2. 看这一层是否配置了：
client_max_body_size
  1. 看文件大小是否超过限制

常见解决办法

整站放宽

server {
    client_max_body_size 50m;
}

单独接口放宽

location = /api/upload {
    client_max_body_size 100m;
    proxy_pass http://127.0.0.1:8080;
}

更推荐第二种，影响更小。

一句话建议

413 基本就是上传大小限制问题，先找 client_max_body_size。

八、414 Request-URI Too Large

常见现象

请求 URL 太长时报错。

常见原因

  • GET 参数太长
  • URL 里塞了过多内容
  • 某些前端拼接方式不合理

排查步骤

  1. 看请求是不是把大量数据塞进了 URL
  2. 看是不是本来应该用 POST，却用了 GET

常见解决办法

  • 改业务请求方式
  • 不要把大段数据放在 URL 里

一句话建议

414 往往不是 Nginx 配置问题，而是请求设计本身有问题。

九、500 Internal Server Error

常见现象

返回：

500 Internal Server Error

常见原因

  • 后端程序报错
  • Nginx 某些内部处理异常
  • 脚本或动态服务异常

排查步骤

  1. 先看 error.log
  2. 再看后端服务日志
  3. 看是所有请求都报 500，还是只有某个接口报 500

一句话建议

500 很多时候不是 Nginx 本体出错，而是后端逻辑出错。

十、502 Bad Gateway

常见现象

返回：

502 Bad Gateway

这是最常见也最容易遇到的报错之一。

常见原因

  • 后端服务没启动
  • proxy_pass 地址写错
  • 后端端口不通
  • 后端程序崩了
  • Unix socket 写错

排查步骤

  1. 先确认后端服务是否真的在运行
  2. 确认 proxy_pass 地址和端口是否正确
  3. 确认 Nginx 所在机器能否访问后端地址
  4. 看 Nginx error.log
  5. 看后端日志

常见解决办法

场景 1：后端没启动

先启动后端，不要只改 Nginx。

场景 2：代理地址写错

比如：

proxy_pass http://127.0.0.1:8080;

如果后端实际跑在 8081，那就一定会 502。

一句话建议

502 大多数时候可以理解成：

Nginx 想找后端，但没找到一个正常可用的后端。

十一、503 Service Unavailable

常见现象

返回：

503 Service Unavailable

常见原因

  • 后端服务暂时不可用
  • 限流或保护策略触发
  • 上游服务全部不可用

排查步骤

  1. 看是不是所有后端都挂了
  2. 看是否配置了限流、熔断类规则
  3. 查看错误日志和上游服务状态

一句话建议

503 更像“服务暂时不给用”，不一定是彻底挂了。

十二、504 Gateway Timeout

常见现象

返回：

504 Gateway Timeout

常见原因

  • 后端处理太慢
  • 数据库查询太慢
  • 网络慢
  • 超时配置太短

排查步骤

  1. 看是不是只有慢接口报 504
  2. 看后端接口实际执行耗时
  3. 看超时配置，比如：
    • proxy_connect_timeout
    • proxy_send_timeout
    • proxy_read_timeout

常见解决办法

临时放宽超时

location /api/report/ {
    proxy_pass http://127.0.0.1:8080;
    proxy_read_timeout 300;
}

但更关键的是查后端为什么慢。

一句话建议

504 常常不是“连不上”，而是“等太久了”。

十三、499 Client Closed Request

常见现象

日志里看到：

499

常见原因

  • 客户端自己断开了连接
  • 用户刷新页面或关闭页面
  • 前端超时取消请求
  • 上游响应太慢，用户等不及

排查步骤

  1. 看是不是慢接口
  2. 看前端是否设置了较短超时
  3. 看用户侧是否频繁取消请求

一句话建议

499 不是 Nginx 主动断，而是客户端先走了。

十四、400 Bad Request

常见现象

返回：

400 Bad Request

常见原因

  • 请求头格式异常
  • Host 不合法
  • 请求体格式异常
  • Header 太大

排查步骤

  1. 看是否是某类特定客户端才会报错
  2. 看是否有超长 Cookie 或 Header
  3. 必要时检查：
client_header_buffer_size
large_client_header_buffers

常见解决办法

例如请求头太大时：

client_header_buffer_size 4k;
large_client_header_buffers 4 16k;

一句话建议

400 常常和请求格式、请求头、Host 有关。

十五、HTTPS 配置失败

常见现象

  • Nginx 启动失败
  • 浏览器提示证书异常
  • HTTPS 无法访问

常见原因

  • 证书路径写错
  • 私钥和证书不匹配
  • 443 端口没开
  • 证书过期
  • 域名和证书不匹配

排查步骤

  1. 先看配置文件中的证书路径是否存在
  2. 再看是否监听了：
listen 443 ssl;
  1. 再看服务器是否开放 443 端口
  2. 最后看浏览器报的是哪种证书错误

常见解决办法

基础配置通常是：

server {
    listen 443 ssl;
    server_name example.com;

    ssl_certificate     /etc/nginx/ssl/example.crt;
    ssl_certificate_key /etc/nginx/ssl/example.key;
}

一句话建议

HTTPS 问题先分清：
是 Nginx 启动失败，还是浏览器信任失败。

十六、静态资源访问异常

常见现象

  • 页面能打开
  • 但 CSS、JS、图片 404
  • 页面样式乱掉

常见原因

  • 静态目录路径写错
  • root 和 alias 用错
  • 前端打包基础路径不对
  • 子路径部署配置不一致

排查步骤

  1. 打开浏览器开发者工具
  2. 看具体哪个资源请求失败
  3. 对照请求路径看 Nginx 实际会去哪个目录找文件
  4. 检查是不是前端资源路径本身就打包错了

一句话建议

页面白屏、样式丢失，很多时候不是后端问题，而是静态资源路径错了。

十七、访问走错 location

常见现象

  • 你明明写了 /api/
  • 请求却走了 /
  • 或者你写了某条规则却完全不生效

常见原因

  • location 优先级理解错了
  • 被更高优先级规则抢走了
  • 被正则规则抢走了
  • 请求根本没进入这个 server

排查步骤

  1. 先确认访问的是哪个域名和端口
  2. 再确认进了哪个 server
  3. 把所有可能命中的 location 列出来
  4. 按优先级判断：
    • =
    • ^~
    • ~ / ~*
    • 普通前缀最长匹配

一句话建议

你觉得是“配置没生效”，很多时候其实只是“命中了另一条规则”。

十八、重载失败

常见现象

执行：

nginx -s reload

后发现服务没有按预期生效，甚至报错。

常见原因

  • 配置语法有问题
  • include 的子配置文件有问题
  • 当前运行的 Nginx 不是你以为的那一套

排查步骤

  1. 先执行：
nginx -t
  1. 看具体加载的是哪个配置文件
  2. 确认你改的是否真是当前运行实例使用的配置

一句话建议

“我明明改了为什么没生效”，有时不是没生效，而是你改错文件了。

十九、改完配置没效果

常见现象

  • 文件已经改了
  • 服务也重载了
  • 但浏览器里看起来还是旧的

常见原因

  • 浏览器缓存
  • CDN 缓存
  • 实际访问的不是这台机器
  • 改的是错误配置文件
  • 改完没有真正 reload 成功

排查步骤

  1. 先确认 nginx -t 是否通过
  2. 再确认 reload 是否成功
  3. 浏览器强制刷新
  4. 检查是否有缓存层
  5. 确认域名是否解析到正确服务器

一句话建议

“没效果”不一定是 Nginx 不工作，也可能是缓存还在工作。

二十、适合新手的排错口诀

如果你不想一下记太多，可以先记这个顺序：

  1. 先看 nginx -t
  2. 再看 error.log
  3. 再看 access.log
  4. 再看域名、端口、路径
  5. 再看 location
  6. 最后看后端服务

这套顺序能解决大部分问题。

二十一、最后总结

Nginx 常见问题，最容易遇到的其实就这些：

  1. 配置语法错
  2. 端口被占用
  3. 路径或目录写错
  4. location 命中错
  5. 上传大小限制
  6. 后端没启动或代理地址错误
  7. 后端超时
  8. HTTPS 配置异常
  9. 缓存导致你以为“配置没生效”

所以排查时，不要乱改，先分类：

  • 是启动类问题
  • 是静态文件类问题
  • 是代理类问题
  • 是超时类问题
