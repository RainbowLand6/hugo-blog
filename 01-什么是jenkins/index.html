01-什么是 Jenkins

一句话理解

Jenkins 是一个自动执行重复开发流程的工具。 最常见的流程是：拉取代码、编译、测试、打包、发布。

以前发布一个项目，可能需要手动执行：

git pull -> mvn package -> 上传 jar -> 重启服务

手动操作的问题是：步骤容易漏、不同人执行结果不一致、出了问题也难追溯。Jenkins 可以把这些步骤写成流水线，每次都按同一规则运行。

CI 和 CD 是什么

名词全称大白话解释
CIContinuous Integration，持续集成代码一合并或提交，就自动编译、测试，尽早发现问题。
CDContinuous Delivery/Deployment，持续交付/部署构建成功后，自动交付给测试环境，或自动部署到目标环境。

一个常见流程：

开发者提交代码
        ↓
Jenkins 拉取代码
        ↓
编译、单元测试、代码检查
        ↓
生成 jar 或 Docker 镜像
        ↓
部署到测试环境
        ↓
人工确认后发布生产

Jenkins 的核心概念

概念含义
ControllerJenkins 的控制端，负责网页、任务调度和保存配置。旧资料中常叫 Master。
Agent真正执行构建命令的机器或容器。
Job一个自动化任务，例如“构建订单服务”。
BuildJob 的一次运行记录。
WorkspaceJenkins 为某次构建准备的工作目录，代码会被拉到这里。
Plugin插件。Jenkins 依靠插件连接 Git、Docker、Maven、企业微信等工具。
Pipeline用代码描述的一系列构建、测试、发布步骤。

什么时候适合用 Jenkins

适合：

  • 有重复的构建、测试、发布动作。
  • 需要多人共享同一套发布流程。
  • 有私有网络、私有服务器或自建 Git 服务。
  • 需要比较灵活的流水线逻辑。

暂时不一定需要：

  • 只是偶尔运行一两条命令。
  • 个人一次性小脚本，没有构建和发布需求。

本章完成标志

你能用自己的话说清楚：Jenkins 不负责“写代码”，它负责让构建、测试和发布这些重复动作自动、可追溯地执行。
